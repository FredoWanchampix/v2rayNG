# v2rayNG WL — форк для белых списков и устойчивости

👉 **Репозиторий этого форка:** https://github.com/FredoWanchampix/v2rayNG

**Основа и история проекта:**
- Оригинальный клиент: [2dust/v2rayNG](https://github.com/2dust/v2rayNG) — ок, который стабильно развивается апстримом и является upstream-источником для нашей синхронизации.
- Предыдущий форк: [elizqmill/v2rayNG](https://github.com/elizqmill/v2rayNG) — автор начал эту работу первым и заложил основу, на которой этот проект вырос.
- Этот форк берёт **изменения и идеи из обоих репозиториев**: благодарна за их вклад и стараюсь сохранять атрибуцию и направление исходов.

Android-клиент V2Ray/Xray на базе [v2rayNG](https://github.com/2dust/v2rayNG), доработанный под три цели:

1. **Работа в сетях с «белыми списками»** — там, где пинг проходит до любого адреса, но скорость на неразрешённых IP искусственно режется шейпингом, а обычная проверка задержки ничего не показывает.
2. **Устойчивость соединения в ограничительных сетях** — периодические обрывы TLS-рукопожатий не роняют обновление подписок и загрузку конфигов.
3. **Расширенный набор протоколов и ядер** — помимо штатных VLESS/VMess/Shadowsocks/Trojan/WireGuard/Hysteria2 добавлены AmneziaWG, NaiveProxy, OpenConnect/AnyConnect, Mimic и FPTN через сайдкар-движки.

**Ключевые слова:** Android VPN, V2Ray, Xray, sing-box, mihomo, Hysteria2, NaiveProxy, OpenConnect, AmneziaWG, Mimic, FPTN, MASQUE, белые списки, DPI, прокси, подписки, certificate pinning.

## Чем этот форк отличается от оригинала

### 1. Поиск стабильных профилей (проверка по белым спискам)

Главный экран → ⋮ → **«Поиск стабильных профилей (проверка БС)»**.

Проверка идёт в два этапа:

1. у всех профилей измеряется реальная задержка через ядро;
2. каждый живой профиль дополнительно проверяется **скачиванием тестового файла** через собственное временное ядро — именно это вскрывает шейпинг белого списка, который не виден по пингу.

Рядом с пингом отображается измеренная скорость:

| | |
|---|---|
| 🟢 `3.4 MB/s` | профиль полностью пригоден |
| 🟠 `420 KB/s` | скорость понижена, но пользоваться можно |
| 🔴 `18 KB/s` | шейпинг белого списка |

- Пинг при проверке скорости **не перезаписывается**.
- У каждого проверенного профиля сохраняется числовое значение скорости.
- Меню ⋮ → **«Сортировать по скорости»**.
- Профили со скоростью `0 кБ/с` удаляются отдельным действием (**«Удалить нулевые»**).

Настраиваемые параметры этапа (Настройки → «Поиск по белым спискам»): количество целевых профилей, таймаут TCP-пинга, размер тестового файла, таймаут скачивания, число прогонов.

### 2. Устойчивость к обрывам TLS

- **Trust-all TLS для служебных загрузок:** проверка сертификатов отключена для загрузки подписок, проверки обновлений и скачивания geo-файлов — в ограничительных сетях middlebox'ы рвут рукопожатия (`SSLHandshakeException: connection closed`).
- **6 попыток загрузки подписки** с экспоненциальным backoff (`min(1500·attempt, 6000)` мс); ретраятся `IOException`/`SSLException`. Одна сброшенная рукопожатие больше не роняет всё обновление подписки.
- **Проверка обновлений через активный профиль** — общий резолвер маршрута решает по состоянию ядра, а не одним TCP-пробником порта: если профиль работает и слушает loopback HTTP inbound, запрос идёт через него (логин/пароль читаются из runtime-конфигурации туннеля). Если профиль работает, но loopback inbound не поднят, запрос явно отклоняется с инструкцией включить локальный прокси — direct-запрос бы обошёл профиль, ведь приложение исключает себя из собственного туннеля.
- **Обновление гео-файлов через активный профиль** — кнопка скачивания открывает меню «Обновить» / «Обновить через активный профиль», работающее в тех же режимах VPN / hev-tun / root / FPTN и использующее тот же резолвер маршрута.

### 3. Конвертеры подписок

В настройках каждой подписки доступны переключатели:

- **Base64 в текст** — разворачивает base64-тело подписки в обычный список ссылок.
- **Кастомные в ссылки** — преобразует JSON-профили в обычные ссылки (`vless://`, `vmess://`, `ss://`, `trojan://`, `hysteria2://`, `tuic://` и др.), редактируемые штатным интерфейсом.

Поддерживаются xray-outbounds, sing-box формат и полные конфиги построчно. Нераспознанные записи сохраняются как кастомные профили (без потери исходного JSON — при экспорте они выгружаются как есть).

Автоматическая обработка **SHA-256 certificate pinning**: при включённой опции подписки профили с заполненным `pinSHA256`/`pinnedCA256` помечаются `insecure`, чтобы pin не ломал соединение.

### 4. Дополнительные протоколы и сайдкар-движки

Форк добавляет протоколы, которых нет в оригинале. Они работают через **сайдкар-движки** — отдельные исполняемые процессы, поднимающие локальный mixed-порт (SOCKS/HTTP), который Xray-ядро использует как восходящий прокси:

| Протокол | Движок | Как подключается |
|---|---|---|
| **AmneziaWG** | `mihomo` (MetaCubeX) | wireguard-outbound с `amnezia-wg-option` (jc/jmin/jmax/s1–s4/h1–h4/i1–i5 и пр.) |
| **NaiveProxy** | `sing-box` | naive-outbound |
| **OpenConnect / AnyConnect** | `sing-box` | endpoint + rule-route |
| **Mimic** | `mimic-client` | Hysteria2-семейство (MTP + TLS-мимикрия), домены мимикрии |
| **FPTN** | `fptn-client` | отдельный TUN в **root-режиме** (см. примечание ниже) |

> **FPTN:** клиент создаёт и владеет собственным TUN-интерфейсом, поэтому заменяет весь стек Xray + hev-tun и работает **только в root-режиме** (Android выделяет единственный VPN-слот). Бинарник `fptn-client` кросс-собирается в CI через NDK и вкладывается в `assets/engines/`.

Движки собираются в GitHub Actions (mihomo — официальный prebuilt, sing-box — из исходников с CGO+NDK clang для naive/cronet, Mimic — кросс-компиляция Go, FPTN — NDK).

### 5. Расширенная диагностика

- TCPing, real ping и **ICMP ping** — из меню главного экрана.
- Отображение задержки до IP-lookup; показ соединения до резолва.
- Расширенное редактирование Hysteria2: выбор obfs (`none`/`salamander`/`gecko`), размеры пакетов для gecko, кнопка получения certificate pin.

### 6. Унаследовано из апстрима 2.4.0

Форк синхронизирован с апстримом и включает его нововведения: **MASQUE (+WARP)**, импорт кастомных outbound из JSON, поиск по элементам proxy-chain, редизайн connection bar, фикс дублей групп подписки.

## Полнота синхронизации с апстримом

Синхронизация выполняется workflow `Sync upstream and build v2rayNG`:

- строгий merge без «тихого» подавления конфликтов — любой неразрешённый конфликт останавливает job и **не трогает master**;
- шаг эквивалентности проверяет, что все файлы, изменённые только апстримом, остались байт-в-байт как в апстриме;
- перед публикацией создаётся резервная ветка предыдущего master;
- каждый релиз содержит **актуальный changelog именно этого релиза** (см. ниже).

## Changelog релизов

Каждый релиз публикует список изменений **относительно предыдущего опубликованного релиза**, а не накопительный дубликат. Предыдущий тег определяется по **времени публикации релиза**, а не лексикографической сортировке имён тегов, поэтому в notes попадают только реально новые коммиты:

- **Коммиты форка** — изменения самого форка с прошлого релиза;
- **Коммиты upstream** — коммиты апстрима, интегрированные этим слиянием.

## Сборка

Сборка APK выполняется GitHub Actions **только по явному запуску** — пуши в master сами по себе ничего не собирают (устранено дублирование сборок). Workflow готовит Android SDK/NDK, собирает native-библиотеки (hev-socks5-tunnel) и сайдкар-движки (mihomo, sing-box, mimic-client, fptn-client), скачивает `libv2ray.aar` и собирает APK для всех ABI + universal, а затем выполняет unit-тесты **блокирующим образом**.
Релиз появляется только при явно выбранном канале: `stable` — стабильный релиз, `prerelease` — бета, `none` — только сборка/проверка. Приложение подписывается релизным keystore через repository secrets, а отладочные сборки без секретов остаются debug-signed.<|close|>

## Установка

Скачайте нужный APK из последнего релиза:

- `universal` — любая архитектура;
- `arm64-v8a` — 64-бит ARM (большинство телефонов с 2017 г.);
- `armeabi-v7a` — 32-бит ARM;
- `x86_64` / `x86` — эмуляторы.

Проверьте контрольные суммы в `SHA256SUMS.txt`.
